# hardad — a Swedish-tutor app demonstrating Docker's supply-chain security stack

A conversational Swedish-language tutor (FastAPI + Anthropic Claude) deployed on Docker Hardened Images. Built and published as a portfolio project to demonstrate hands-on use of Docker's full supply-chain security pipeline: hardened base images, build-time SBOMs and SLSA provenance, cosign keyless signatures, and (in subsequent versions) admission-time policy enforcement on Kubernetes.

The application itself is the vehicle. The interesting part is what's *attached* to the image: signed evidence about how it was built, what's in it, and who vouches for it.

> **Note**: This is a demo image built as part of a job application for the Senior Solutions Engineer role at Docker. Not intended for production use. The live deployment is at [lenie.selfhost.eu/docker_demo](https://lenie.selfhost.eu/docker_demo) (access by invitation).

## What this image demonstrates

| Layer | What's here |
|---|---|
| Base image | `dhi.io/python:3.12` — Docker Hardened Image, distroless, near-zero CVEs, SLSA Build Level 3 from Docker |
| App | FastAPI server backing a conversational Swedish tutor, calling Anthropic Claude as the agent's language model |
| SBOM | SPDX 2.3 + CycloneDX, generated at build time by BuildKit, attached as in-toto attestation |
| Provenance | SLSA v0.2 build attestation, generated by BuildKit, attached as in-toto attestation |
| Signature | Image and attestations signed via cosign keyless (Sigstore), recorded in Rekor's public transparency log |
| Source | [github.com/LennartOnGit/hardad](https://github.com/LennartOnGit/hardad) |

## Hardened vs baseline metrics

The same FastAPI app, same dependency closure, two different base images:

| Metric | Baseline (`python:3.12-slim`) | Hardened (`dhi.io/python:3.12`) | Change |
|---|---|---|---|
| Image size | 86 MB | 44 MB | -49% |
| Total packages | 167 | 91 | -46% |
| Debian-layer packages | 122 | 43 | -65% |
| Total CVEs | 33 | 20 | -39% |
| Critical + High CVEs | 3 | 1 | -67% |

The hardened image's remaining High is fixable by bumping the runtime to DHI Python 3.13 — a one-line Dockerfile change. Held at 3.12 here for an apples-to-apples comparison against the baseline. Full breakdown in [the project's writeup](https://github.com/LennartOnGit/hardad).

## Verifying signatures

The image and its attestations are signed via cosign keyless. To verify:

```bash
# Verify the image signature
cosign verify \
  --certificate-identity <signing-identity> \
  --certificate-oidc-issuer https://accounts.google.com \
  lennartondocker/hardad:hardened

# Verify the SBOM attestation
cosign verify-attestation \
  --certificate-identity <signing-identity> \
  --certificate-oidc-issuer https://accounts.google.com \
  --type spdxjson \
  lennartondocker/hardad:hardened

# Verify the SLSA provenance
cosign verify-attestation \
  --certificate-identity <signing-identity> \
  --certificate-oidc-issuer https://accounts.google.com \
  --type slsaprovenance \
  lennartondocker/hardad:hardened
```

The signing identity and exact verification commands are documented in the [GitHub repo](https://github.com/LennartOnGit/hardad#verifying-this-image).

## Inspecting the SBOM and provenance

```bash
# View the SBOM (SPDX format)
docker buildx imagetools inspect lennartondocker/hardad:hardened \
  --format "{{ json .SBOM }}"

# View the SLSA provenance
docker buildx imagetools inspect lennartondocker/hardad:hardened \
  --format "{{ json .Provenance }}"
```

## Tags

## Running the image

This image is part of a larger stack (FastAPI app, Postgres, MinIO, Authentik). The image alone won't do anything useful without those services. See the [GitHub repo](https://github.com/LennartOnGit/hardad) for the Compose / Helm definitions of the full stack.

For development inspection only:

```bash
docker pull lennartondocker/hardad:hardened
docker scout cves lennartondocker/hardad:hardened
docker scout sbom --format spdx lennartondocker/hardad:hardened
```
